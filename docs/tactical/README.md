# Native Tactical Docs

Native-first Rust implementation tacticals live here.

Use zero-padded numeric prefixes for new native tactical docs: `000-topic.md`, `001-next-topic.md`, and so on. Keep one active implementation slice per doc. Parent sequencing checklists are allowed when they keep the native workstream focused; mark them clearly as parent docs and add every new native tactical to this index.

For vanilla behavior and visual correctness, use `../../reference/minecraft-1.17.1/src/` first. That includes renderer-facing behavior such as model baking, texture atlas stitching, mipmap/filter state, light texture math, fog, sky, render layers, particles, and section traversal. For native platform, renderer-boundary mechanics, performance tooling, Android, or XR tacticals, use the sibling Playbox repo at `~/code/playbox` as a pattern library after the Java behavior is understood. Start with `~/code/playbox/Cargo.toml`, `docs/architecture/rendering.md`, `docs/architecture/platforms.md`, `android/README.md`, and `android-xr/README.md`. Mclone's native `profile.dev` is optimized at `opt-level = 2`, following Playbox, so debug movement/render smokes are less misleading while still retaining debug assertions.

For durable subsystem progress indexes, see [`../topics/`](../topics/README.md). In particular, current native performance priority lives in [`../topics/performance.md`](../topics/performance.md), and current lighting progress and next solver/status/rendering slices live in [`../topics/lighting.md`](../topics/lighting.md). The tactical docs below remain the detailed implementation records.

**Active render-worker direction:** desktop and native-web should run the same render compile topology behind one shared `RenderSectionCompiler` trait, with desktop using Rust structs over channels and web using a resident `SharedArrayBuffer` ring behind the same trait — not a common serialized ABI on desktop. Web converges on desktop's per-frame incremental streaming loop, and JavaScript shrinks to worker construction, wakeups, and diagnostics. The bigger picture lives in [`067-shared-render-worker-architecture.md`](067-shared-render-worker-architecture.md), which supersedes `065` and `066`. The parent native-thread/Web-Worker topology and the server-runner / worldgen / light / transport lanes stay in [`062-shared-threading-topology.md`](062-shared-threading-topology.md); the shared render-session boundary stays in [`061-shared-engine-web-adapter-refactor.md`](061-shared-engine-web-adapter-refactor.md).
