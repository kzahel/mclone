# 050: Native Leaf Sky Render Parity

Status: completed first pass.

## Purpose

Fix the dark tree canopy tops visible after the first retained lighting
performance slices. The scene was lit and nonblank, but foliage top faces could
render nearly black while the same view looked normal in fullbright.

This is a small Java-parity correction between the lighting solver and render
handoff, not a new lighting architecture slice.

## Reference Source

Read before implementation:

- `reference/minecraft-1.17.1/src/net/minecraft/world/level/block/LeavesBlock.java`
- `reference/minecraft-1.17.1/src/net/minecraft/world/level/lighting/SkyLightSectionStorage.java`

Important reference shape:

- `LeavesBlock.getLightBlock(...)` returns `1`, so leaves attenuate skylight
  but do not behave like fully opaque solids.
- `SkyLightSectionStorage.getLightValue(...)` does not treat every missing
  sky data layer as darkness. It searches upward through missing sections at
  the same local coordinates and returns full sky (`15`) when the read reaches
  the top without finding a stored layer.

## Scope

Landed in this slice:

- `mclone-worldgen::block_light_opacity(...)` now returns `1` for the native
  leaf ids currently generated by trees: oak, birch, and spruce.
- `mclone-mesh::TexturedChunkMeshInput` now samples block light only from the
  exact packed section, but samples sky light with Java-style upward lookup
  across omitted sky sections.
- The mesh sampler returns full sky when a missing sky section is above all
  stored sky layers, fixing top faces that sample the air block just above a
  section boundary.
- Added unit tests for leaf opacity and for both mesh sky lookup cases:
  missing section above data reads as open sky, and missing section below a
  later sky layer climbs to that next layer.

## Out Of Scope

- Full vanilla `BlockState.getLightBlock(...)` tables beyond the current
  generated block set.
- Java `SkyLightEngine.checkNeighborsAfterUpdate(...)` skip-through propagation
  for graph updates across missing vertical storage sections.
- Java `LightTexture` brightness curves.
- `ModelBlockRenderer.AmbientOcclusionFace` and solid block ambient occlusion.
- Live block-change `checkBlock` deltas and render-section dirtying by changed
  light sections.

## Result

The previous lit capture showed dark/black foliage-top patches that did not
appear in fullbright. After this slice, the same seed/view renders canopy tops
in the same sane green range as the fullbright comparison while retaining
server-side lighting.

Validated screenshots:

```text
/tmp/mclone-light-leaf-sky-sampler-lit.png
/tmp/mclone-light-leaf-sky-sampler-fullbright.png
```

Both captures rendered `960x540`, `166` cached sections, `26` drawn sections,
and nonblank terrain.

Radius-5 lighting-enabled perf stayed in the same range as the prior source
storage slice:

| Metric | P6.10 source storage | P6.11 leaf/sky render parity |
|---|---:|---:|
| total elapsed | `1,927.655 ms` | `1,945.648 ms` |
| light-status compute | `455.894 ms` | `460.263 ms` |
| `LevelLightEngine.run_all_updates` | `402.035 ms` | `405.848 ms` |
| block graph drain | `30.788 ms` | `30.681 ms` |
| sky graph drain | `371.212 ms` | `375.135 ms` |
| block processed nodes | `52,348` | `52,348` |
| sky processed nodes | `794,466` | `794,963` |

Interpretation: the visual fix is not a material startup performance change.
The small sky-node delta is expected because leaves now attenuate skylight by
one level instead of blocking it completely.

## Next

The next likely visual parity slice is Java block-model lighting on the render
side:

- read `BlockModelRenderer`, `ModelBlockRenderer`, and `LightTexture`
- port the vanilla per-face brightness/lightmap shape for flat rendering first
- then port `AmbientOcclusionFace` blending for solid blocks
- keep the implementation split along render/model/lightmap boundaries rather
  than growing the mesh builder into a giant renderer module

Sky skip-through graph propagation remains a solver parity item, but the
current visible foliage-top bug was the render handoff's missing-section read
semantics.
